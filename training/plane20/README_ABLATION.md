# Парная ablation: плотность × добавленный шум

Сервер: `kisor@dexter:/raid/kisor/projects/zb/plane20_stardist`.
Данные: `dataset_ablation`, новые результаты: `runs/ablation_center32`.
Предыдущие данные и результаты не перезаписываются.

## Запуск всех четырёх обучений в одном терминале

```bash
ssh kisor@dexter
cd /raid/kisor/projects/zb/plane20_stardist/src
CUDA_VISIBLE_DEVICES=1 bash training/plane20/run_ablation_training.sh
```

Четыре независимых процесса одновременно используют одну выбранную A100 80GB.
В каждом лимит TF 16384 MiB, всего 64 GiB. Это ограничение аллокатора,
драйвер/контексты требуют дополнительной памяти. На занятой GPU убедитесь,
что свободно достаточно памяти. CUDA MPS и дополнительные сервисы не нужны.
Параллельность не гарантирует ускорения относительно последовательного запуска.
CPU: по два intra-op/OMP потока и одному inter-op/BLAS на процесс.

Общий stdout помечается `[normal_noisy]`, `[normal_clean]`, `[half_noisy]`,
`[half_clean]`. Полные логи отдельно: `runs/ablation_center32/logs/*.log`.
Ctrl-C останавливает все дочерние процессы. Ошибка одного обучения останавливает
остальные. Продолжение всех с последнего сохранённого epoch:

```bash
CUDA_VISIBLE_DEVICES=1 bash training/plane20/run_ablation_training.sh --resume
```

Если процесс остановлен до первого checkpoint, его каталог нужно переместить
или выбрать новый общий `--output`; launcher не удаляет результаты автоматически.
Без `--resume` существующие каталоги обучений запрещены.
Для другой серии: `--output ../runs/ablation_center32_repeat`.

## Что сравнивается

| Каталог | Плотность | Добавленный коррелированный шум |
|---|---|---|
| normal_noisy | исходная | исходный |
| normal_clean | исходная | выключен |
| half_noisy | случайные 50% исходных сом | исходный |
| half_clean | те же 50% | выключен |

На каждую постановку 64 train / 8 val / 8 test сцен. Seed генерации 20261113
сохранён: normal_noisy воспроизводит исходный набор. Между split сцены независимы;
между постановками каждая сцена парная. Морфология, амплитуды и angular coefficients
сначала определяются для полного набора, затем случайно выбирается половина
без возвращения, с сохранением порядка. Пересчёт фотометрии для оставшихся
объектов не производится; поле фокуса, оптика, background, normalizer и noise_sigma
сохранены. Низкая плотность не компенсируется усилением яркости.
Используется исходный нелинейный contrast_signal: он применяется к новой сумме
сигналов и сохраняет её суммарную энергию; разность dense/sparse не обязана быть
точной суммой удалённых клеток после этой коррекции.

Clean = `round(clip(background + rendered_cells))`; noisy добавляет исходное
`unit_noise * noise_sigma` перед теми же clip/round. Из background не удаляются
текстуры/остаточные флуктуации профиля. Размытие и пересечения остаются.

В каждом npz есть `parent_indices` и полные `sampling_centers` для аудита.
Последние используются ТОЛЬКО для выбора областей изображения: правило 80%
тканевых / 20% равномерных кропов применяется по полному набору центров во всех
вариантах. Благодаря этому координаты кропов совпадают даже при меньшем числе
объектов. Цели, маски и метрики используют только фактически оставленные центры.
Пиксели нормируются прежним P5–P95 отдельно для каждого кропа; это одинаковое
правило, не фиксированные между вариантами значения percentiles.

## Обучение и оценка

Архитектура, loss и гиперпараметры из `README_CENTER_MASK.md` не меняются:
base32, depth3, 128px, batch32, max_masks64, 100 epochs × 200 steps,
validation 16 batches, seed42, Adam3e-4, ReduceLROnPlateau patience8.
Инициализация и последовательность координат кропов одинаковые.
Число объектов на кроп и абсолютные значения loss при разной плотности
закономерно различаются; ориентироваться нужно на instance-метрики.

После завершения всех четырёх обучений launcher последовательно оценивает
лучшие по val_loss веса на одинаковых 24 val-кропах (seed991/start32),
center threshold0.3, mask threshold0.5. Каждый отчёт содержит
`predicted_centers`, `oracle_centers`, `center_detection`.
Сводка: `runs/ablation_center32/comparison.json`.
Test не используется. Пороги не подбираются отдельно для каждой постановки.
Это первая контролируемая проверка с одним seed, не оценка разброса эксперимента.
`--skip-evaluation` отключает только заключительную instance-оценку.

Для технической проверки в отдельном каталоге:

```bash
CUDA_VISIBLE_DEVICES=1 bash training/plane20/run_ablation_training.sh \
  --output ../verification/ablation_smoke --epochs 1 --steps 3 --val-steps 1
```

Полное обучение при подготовке не запускается.

Воспроизведение генерации (выходной каталог должен отсутствовать):

```bash
source training/plane20/activate.sh
OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 python -m training.plane20.generate_ablation \
  --profile ../assets/profile.npz --output ../dataset_ablation --workers 8
```

Генератор записывает manifest/hash/config и COMPLETE только после успешного
завершения. Для обучения center-mask старый дисковый StarDist target-cache
не нужен: цели кэшируются в RAM по прежнему механизму.

## Выполненная техническая проверка

- 15 unit-тестов прошли локально и в серверном TF2.15.1 окружении.
- Аудит всех 80 парных сцен: normal_noisy совпадает с прежними данными
  по всем исходным массивам; геометрия/амплитуды/полные sparse-маски половины
  в точности соответствуют выбранным исходным объектам; manifests/hash проверены.
- По 100 индексов кропов в каждом split: координаты совпали во всех вариантах.
- Четыре процесса одновременно выполнили 1 epoch × 3 steps, batch32,
  validation1, сохранили веса/optimizer state и прошли заключительную
  instance-оценку. Это проверка запуска, не качества модели.
- Проверка использует отдельный `verification/ablation_smoke_data`:
  две парные сцены для train/val; это не основной набор 64/8/8.
- На GPU1 занято примерно 70 GiB с учётом существовавшего процесса ~4 GiB.
- Основные `runs/ablation_center32/*` при подготовке не создавались.

Аудит: `dataset_ablation/audit.json`; логи проверки:
`verification/ablation-smoke.log`, `verification/ablation-unit-tests.log`.
