# Первое обучение Plane20: U-Net + StarDist

Новый отдельный эксперимент с детектором центров и независимыми масками
описан в [README_CENTER_MASK.md](README_CENTER_MASK.md). Ниже — прежние
StarDist-запуски, которые сохраняются для сравнения.

Подготовленное окружение на `kisor@dexter`:
`/raid/kisor/projects/zb/plane20_stardist`.

Это официальный `StarDist2D` 0.9.1 с U-Net глубины 3, базой 32 фильтра,
32 лучами и выходной сеткой `(1,1)`. TensorFlow 2.15.1, Python 3.11.
Вход — 128×128 исходных пикселей, P5–P95 отдельно для каждого входа,
clipping в [0,1]. Центральные 96×96 участвуют в loss. BCE для вероятности,
взвешенный MAE для расстояний; веса 1 и 0.2. Adam, LR 3e-4,
снижение LR вдвое после 8 эпох без улучшения validation loss.

## Запуск на сервере

Продолжение текущего остановленного `runs/first` с последнего checkpoint:

```bash
ssh kisor@dexter
cd /raid/kisor/projects/zb/plane20_stardist/src
CUDA_VISIBLE_DEVICES=1 bash training/plane20/run_training.sh --resume
```

По умолчанию: 100 эпох × 200 шагов, batch 32; 16 фиксированных validation
batch на эпоху. Длительное обучение само по себе при подготовке не запускается.
GPU 1 — A100; GPU 3 — служебная Display GPU, её не использовать.

Для фонового запуска с сохранением процесса после выхода из SSH:

```bash
tmux new-session -d -s plane20-train \
  'cd /raid/kisor/projects/zb/plane20_stardist/src && CUDA_VISIBLE_DEVICES=1 bash training/plane20/run_training.sh --resume > ../train.log 2>&1'
tail -f /raid/kisor/projects/zb/plane20_stardist/train.log
```

`CUDA_VISIBLE_DEVICES=1,2` включает TensorFlow MirroredStrategy на двух A100.
Batch задаётся суммарно на все GPU и должен делиться на их число.
Для небольшой сети одна A100 — исходный вариант. Цели предрассчитаны;
во время обучения загрузчик только вырезает окна из карт.

Продолжение прерванного запуска, включая состояние Adam и learning rate:

```bash
CUDA_VISIBLE_DEVICES=1 bash training/plane20/run_training.sh --resume
```

Для нового эксперимента уберите `--resume` и укажите новое `--output /absolute/path`.
Существующий run без `--resume` защищён от перезаписи. Возобновлять следует
с теми же `--data`, `--seed`, `--steps` и `--batch-size`.

### Что оптимизирует loss

Полный loss: `BCE(probability) + 0.2 * weighted_MAE(radial_distances)`.
Вероятность — геометрическая мягкая цель `max(1-rho,0)`, а не яркость
пикселя. В перекрытии выбирается максимум нормированной глубины внутри
эллипса. MAE усредняется по32направлениям и взвешивается этой же
вероятностью; итог нормируется на сумму весов. В halo probability=-1
исключает BCE, вес distance-loss=0. Фоновая регуляризация расстояний=0.
Измерять правильность расстояний на фоне не требуется: детекции там
подавляет probability-ветвь.

Это плотная регрессия к конкретной GT-геометрии в каждом пикселе.
Внутри loss нет NMS, счётчика объектов или one-to-one сопоставления
готовых масок. NMS действует только при выделении экземпляров.
Поэтому loss сам по себе не гарантирует отсутствие дубликатов и не
заменяет instance-метрики. В instance-оценке применяется однозначное
сопоставление при IoU≥0.5: одной GT-соме нельзя засчитать несколько
предсказаний. Остальные становятся FP.

Проверка плотностного prior без сети — гексагональная упаковка кругов
диаметра8.12857px в ярких областях после Gaussian sigma3. Шаг упаковки
и порог яркости выбраны на тех же16validation-кропах, что пороги CNN.
На тех же24test-кропах получены precision0.253, recall0.556, F1=0.348
против F1=0.747 у первой модели. Это сравнение с конкретным простым
prior, а не доказательство отсутствия prior в предсказаниях CNN.
Отчёт: `verification/final_diagnosis/packed-circle-baseline.json`.

## Данные и воспроизведение

`assets/profile.npz` содержит необходимые калибровочные карты и исходные
JSON с параметрами. Полный фильм для обучения не нужен. Отдельно перенесён
`assets/real_frame500.tiff` для просмотра переноса на реальный кадр.

Датасет: 64 независимые train-сцены, 8 validation, 8 test. Seeds/геометрия
между разделами не повторяются. Кропы извлекаются во время обучения,
80% выборки ориентировано на ткань, 20% допускает любую часть кадра.
Больших поворотов/отражений пока нет, чтобы сохранить ориентацию сом
и направленность подогнанного размытия.

Генератор повторно использует существующие `relaxed_centers`,
`sample_morphology`, `build_empirical_scene`, `thinner_shell_patch`,
поля коррелированного усиления, оптику, контраст и шум текущего профиля.
Сначала размещаются 6830 кандидатов по исходной поддержке упаковки,
затем удаляются эллипсы, не помещающиеся в разрешённую ткань.
Число сохранившихся клеток может меняться от сцены к сцене.

Расположение, размеры/углы, усиления, оболочки, фокус и шум пересэмплируются.
Анатомическая маска, density prior, фон, normalizer и noise_sigma остаются
от выбранной калибровки. Дополнительного расширения диапазонов параметров
в первой версии нет. Старый normalizer не переоценивается под новую геометрию.

Каждая сцена хранит изображение, геометрию и полные sparse instance-маски,
включая перекрытия. `manifest.jsonl` содержит seeds и SHA256 файлов;
`config.json` — параметры и SHA256 профиля. `COMPLETE` появляется только
после завершения генерации всех сцен.

### Предварительно рассчитанные цели

На сервере уже подготовлен `dataset/target_cache` для всех 80 сцен.
В нём находятся несжатые `prob.npy` и `dist.npy` для каждой сцены,
общим объёмом около 4.4 ГиБ. Загрузчик использует read-only memory mapping,
сохраняет изображения сцен в RAM и извлекает только нужное окно карт.
Области halo маскируются на копии кропа, исходные карты не изменяются.

Цели рассчитывает прежняя функция `data.targets` плитками без halo;
границы плиток не обрезают полные эллипсы. Для кропа из тех же seed/index
изображение, вероятность, расстояния и маска loss побитово совпадают со
старым расчётом. Сеть, loss, выборка кропов и batch size не менялись.
Обучение по-прежнему использует один worker; дополнительные процессы
нужны только при разовом предрасчёте.

Кэш связан с SHA256 манифеста сцен, числом лучей и реализацией функции
целей. Незавершённый или несовместимый кэш не используется для обучения.
Предрасчёт можно повторить: завершённые сцены с теми же параметрами
переиспользуются. Старые checkpoint совместимы с новым загрузчиком.

На Dexter проверены 96 кропов из train/val/test: побитовое совпадение со
старым расчётом. Подготовка 128 кропов после прогрева ускорилась с 10.51
до 0.142 с; первое чтение кэша заняло 1.72 с. На отдельной копии checkpoint
30 шагов обучения + 4 validation batch размера32 заняли 4.77 с после
компиляции первого прохода. Это короткий benchmark, а не замер полной
эпохи из 200+16 шагов. Полное обучение автоматически не запускалось.
Отчёты: `verification/cache-validation.json` и `verification/cache-benchmark.log`.

## Полные контуры и перекрытия

Вместо расстояний по обрезанным ownership-маскам `data.targets` аналитически
решает пересечение каждого луча с полным эллипсом. Если пиксель находится
в нескольких сомах, выбирается сома с наибольшей нормированной глубиной
внутри эллипса. Probability target — `max(1-rho,0)`, максимум по сомам;
это **вариант стандартных целей StarDist**, а не нормированный EDT по
неперекрывающемуся label-растру. Архитектура, losses и NMS — официальные.

Перекрытие не обрезает целевой контур. Однако одна пара dense-выходов
по-прежнему описывает только один экземпляр на пиксель. Стандартный NMS
может подавлять сильно перекрытые клетки; исходное значение NMS 0.7.
Это первое приближение, не MultiStar и не решение полностью скрытых клеток.
Все сгенерированные клетки пока участвуют в целях, без фильтра видимости.

## Оценка и предсказание

После обучения:

```bash
source training/plane20/activate.sh
python -m training.plane20.evaluate \
  --run ../runs/first --data ../dataset --split val --crops 32 \
  --output ../runs/first/validation_instances.json
python -m training.plane20.predict \
  --run ../runs/first --image ../assets/real_frame500.tiff \
  --output ../runs/first/real_frame500
```

`--threshold` (по умолчанию 0.4) и `--nms` (0.7) подбираются на validation.
После фиксации порогов запускается `evaluate --split test` с новым output.
Оценка включает precision/recall/F1 и средний IoU сопоставленных экземпляров,
однозначное сопоставление при IoU ≥0.5; полные перекрывающиеся маски не
преобразуются в единственный label-растр. Это метрики **синтетики**.
Честная оценка реального переноса требует полностью размеченных реальных кропов.

Inference использует окна 128×128 с halo16 и шагом96. Из каждого окна
принимаются кандидаты в центральных96×96, затем удаляются практически
совпадающие дубликаты у швов. Пересечение масок само по себе не удаляет
объекты после объединения окон. Внутри окна действует стандартный NMS.

Результат: `instances.npz` с полными sparse-масками, координатами полигонов
и уверенностями; `overlay.png`; `labels_preview.tiff`. Последний файл имеет
один ID на пиксель и служит только для просмотра.

В `runs/first/model/` находятся конфигурация, лучшие и последние веса;
в `runs/first/state/` — возобновляемое состояние, в `history.jsonl` — метрики
по эпохам. Лучшие веса выбираются по synthetic validation loss.

## Проверки подготовки

Проведены обучение на одной A100, продолжение из checkpoint, обучение на
двух A100 через MirroredStrategy, вычисление instance-метрик и tiled inference
на реальном кадре. Короткие запуски находятся в `runs/smoke` и
`runs/smoke_multi_gpu`; это технические проверки, не обученная рабочая модель.
Эти короткие запуски выполнялись отдельно от основного `runs/first`.

`dataset-audit.json` фиксирует проверку всех 80 файлов: SHA256, уникальность
seeds, offsets полных масок, ненулевую площадь каждой маски и отсутствие
их пикселей в области исключения. Число сом: 5494–5601, среднее 5554.8.
`assets/generator_qa.png` сравнивает исходную выбранную сцену с новой.

Дополнительная проверка на четырёх фиксированных train-кропах за 1000
обновлений снизила MAE лучей с 3.77 до 0.51 px, probability KLD — с 0.222
до 0.006. Результат записан в `overfit-check.json`; диагностические веса
хранятся отдельно и не используются как старт основного обучения.

Локальные проверки аналитических целей:
